# ライフログ Android-first UX v1 — 2026-11-08

## 課題と根拠
- 本人から「画面がとても使いにくい」「使う側として見たい状況と見なくてよいものが混在」「デザインもいけてない」とのフィードバック。
- 現行App.tsxはロングスクロール：体重→パスキー設定→手入力→グラフ→飲酒→食事→会食→期間比較→行動実験→CSV取込→監査。
- 詳細な技術用語（監査、欠測NULL、認証等）が日常利用を妨げる。一方、現時点で実際の本人利用頻度、Android実機のタップ位置・読了率は計測していない。

## 情報アーキテクチャ

| タブ | 日常価値 | 初期表示 | 隠す情報 |
| --- | --- | --- | --- |
| ホーム | 状況確認と最短入力 | 最新体重・歩数（取得元と測定日）、飲酒1タップ、体重推移 | CSV/監査/パスキー/詳細表/高度設定 |
| 記録 | 今日と過去の手入力 | 体重・歩数、飲酒、食事、飲みの場 | 手入力履歴の編集・取消は展開して使用 |
| ふりかえり | 変化を比較・検証 | 2期間比較、行動実験 | 利用しない管理系項目 |
| データ管理 | 取込・エクスポート・認証 | CSV取込 | CSV出力・取込監査・認証は展開して使用 |

ホームに数字を載せる条件：最新の**観測値**のみ。観測なしは「—」。表示の優先順位は体重ECLEAR＞同日手入力、歩数Google Fit＞同日手入力。日付は必ず隣に表示し、昨日以前の歩数を「今日の歩数」と誤認させない。NULLを0へ変換しない。

## モバイル設計
- Android Chrome 390pxを基準に、430px、800px以上の幅も検証する。
- Mobile：4項目の固定下部ナビ。safe-area-inset-bottomを考慮し、各操作領域44px以上。
- Desktop：同じ4項目の横ナビ。意味的な見出し、ARIA現在ページ、keyboard focus、入力ラベルを保持。
- UIスタイル：背景 #f5f7f6、文字 #172b34、アクセント #087c76、控えめな枠線・余白・丸み。カードは状況確認のみに使用し、nested cardsを増やさない。
- 色だけで状態を区別せず、追加・更新・スキップ件数と日本語を維持。グラフの観測ゼロや欠測表示は保全。
- URL hashでタブを保持（再読み込み、ブラウザ戻る）。本番の認証ルート・Worker APIへの変更は新規read-only dashboard以外なし。

## 表示上の制限・残る受入
- homeの飲酒杯数は*入力された杯数*であり、未記録を0杯の確定値とは扱わない。
- 記録タブ・管理タブの折りたたみは操作の優先順位を下げるだけで、機能削除ではない。
- 目標下限/上限/目標日は既存の画面内仮値。保存や実体に影響しない。目標値の確定は別途。
- 技術テストでは機能・認証・390pxレンダリングの一部を判定できるが、本人Android実機の使いやすさの判定には本人の画面確認が必要。
- Remote D1、Secrets、Migration、他Worker、Production、個人データには変更を加えない。
